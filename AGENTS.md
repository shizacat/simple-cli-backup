# Правила

## Линтинг

Python-код проверяй и форматируй через [black](https://black.readthedocs.io/) со стандартными настройками.

- После правок в `*.py` запускай `uv run black .`
- Перед завершением задачи `uv run black --check .` должен проходить без ошибок
- Не оставляй отступы табами и не подстраивай стиль вручную в обход black

## Места хранения

Все места хранения описывай в пакете `sback/places`. Базовый класс остаётся в `sback/lib/place_base.py`.

## Цели

Все цели описывай в пакете `sback/targets`. Базовый класс остаётся в `sback/lib/target_base.py`.

## Уведомления

Все уведомления описывай в пакете `sback/notices`. Базовый класс остаётся в `sback/lib/notify_base.py`.

## Исключения

Все классы исключений определяй в `sback/lib/exception.py`. В других модулях их не объявляй, только импортируй.

```python
from sback.lib.exception import PlaceError

raise PlaceError("тип места не зарегистрирован")
```

## Changelog

Каждое изменение в проекте фиксируй в `changelog.md`, в секции `## [Unreleased]`, до завершения задачи.

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Пункт — одна строка по-русски, в стиле уже существующих записей. Категория:

- `Added` — новая возможность
- `Changed` — изменение существующего поведения
- `Deprecated` — то, что скоро уберут
- `Removed` — удалённое
- `Fixed` — исправление ошибки
- `Security` — исправление уязвимости

Если подходящей категории в `Unreleased` ещё нет, добавь её. Версию не поднимай и пункты из `Unreleased` в релиз не переноси, пока пользователь явно не попросит.

```markdown
## [Unreleased]

### Added

- Опция `--dry-run` для команды backup
```

## Документирование кода

В докстринге метода с аргументами обязательно описывай каждый аргумент в секции `Args`. `self` и `cls` не указывай.

В докстринге функции, которая может вызывать исключение, обязательно указывай секцию `Raises` с типом и причиной.

В докстринге метода, который что-то возвращает, обязательно указывай секцию `Returns` с описанием результата.
